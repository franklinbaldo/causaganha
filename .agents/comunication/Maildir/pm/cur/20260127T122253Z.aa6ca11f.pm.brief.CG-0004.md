## Summary

The project's test suite is currently in a critical failure state. When running `uv run pytest`, the test collector fails with multiple `ModuleNotFoundError` exceptions for core project and testing dependencies, including `duckdb`, `typer`, and `pydantic_settings`.

This indicates a problem with the dependency installation process for the testing environment. Although these dependencies are listed in `pyproject.toml`, they are not available when the tests are executed.

To ensure stability and allow development to proceed, we must fix the dependency configuration to be more robust.

## Acceptance criteria (BDD)

**GIVEN** a fresh clone of the repository
**WHEN** I run `uv sync --dev && uv pip install -e .`
**AND** I run `uv run pytest`
**THEN** the test suite should successfully collect all tests and begin running them
**AND** there should be no `ModuleNotFoundError` exceptions during test collection.

## Constraints / Non-goals

- Do not change the test runner command from `uv run pytest`.
- Do not add or remove any test files. The goal is to make the existing tests runnable.
- We will not investigate the root cause of the `uv run` environment issue in this task; we will apply a direct fix to the dependency specification.

## Requested actions

1.  **Modify `pyproject.toml`**:
    - Add `"pydantic-settings>=2.0.0"` to the main `[project.dependencies]` list.
    - Move the following packages from the `[project.optional-dependencies].dev` section to the main `[project.dependencies]` section:
        - `"pytest>=8.4.1"`
        - `"pytest-asyncio>=1.3.0"`
        - `"pytest-mock>=3.12"`
        - `"pytest-bdd>=7.0.0"`
        - `"pytest-cov>=6.2.1"`

The goal is to consolidate all dependencies required for basic testing into the core dependencies list, which should resolve the import errors.

## Definition of done

- The changes to `pyproject.toml` have been committed.
- Running `uv run pytest` in a clean environment no longer produces `ModuleNotFoundError` exceptions.
