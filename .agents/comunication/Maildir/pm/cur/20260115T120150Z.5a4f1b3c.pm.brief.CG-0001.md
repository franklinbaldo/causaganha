## Summary
To align with the project's current "Phase 4: Hardening and Documentation", this brief initiates the creation of a robust, automated documentation system. This will improve maintainability and make the project more accessible to new contributors.

## Acceptance criteria (BDD)
```gherkin
Feature: Automated Documentation System

  Scenario: Developer wants to understand the project
    Given a developer has cloned the repository
    When they run "uv run mkdocs serve"
    Then they should see a local website with project documentation.

  Scenario: Documentation is generated from code
    Given the project has a documentation website
    When a developer views the documentation for a core module
    Then the documentation should be generated from the Python docstrings of that module
    And it should reflect the latest changes in the code.

  Scenario: High-level architecture is documented
    Given the project documentation
    When a developer navigates to the "Architecture" section
    Then they should see a clear explanation of the system's design (Modular Monolith, Hexagonal-ish), key components, and data flow.
```

## Constraints / Non-goals
- **Do not** manually write API documentation. The documentation should be generated from docstrings.
- **Do not** change the existing project structure.
- For this initial setup, focus on the core modules: `pipeline`, `storage`, and `api`. Other modules can be added later.

## Requested actions
1.  **Add Dependencies**: Add the following packages to the `[project.optional-dependencies.dev]` section in `pyproject.toml`:
    - `mkdocs`
    - `mkdocs-material`
    - `pytest-bdd` (to fix a pre-existing issue with the test suite).
2.  **Configure MkDocs**: Create a `mkdocs.yml` file at the root of the repository. Configure it to use the Material theme and to generate documentation from the docstrings in `src/causaganha/`.
3.  **Create Initial Docs**:
    - Create a main documentation entrypoint at `docs/index.md`.
    - Create a new high-level architecture document at `docs/architecture.md`. This document should summarize the information found in `CLAUDE.md` and `README.md`.
4.  **Enhance Docstrings**: Review and enhance the docstrings in the main functions and classes of the following modules to ensure they are clear and will generate useful documentation:
    - `src/causaganha/pipeline/`
    - `src/causaganha/storage/`
    - `src/causaganha/api/`
5.  **Add Scripts**: Add a script to `pyproject.toml` under `[tool.uv.scripts]` to run the docs server: `docs = "mkdocs serve"`.

## Definition of done
- All requested actions are completed.
- The command `uv run docs` successfully starts a local documentation server.
- The generated documentation website meets all acceptance criteria.
