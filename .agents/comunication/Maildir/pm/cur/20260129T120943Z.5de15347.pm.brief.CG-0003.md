## Summary

The project's test suite is critically broken and unusable. Executing `uv run pytest` results in 8 `ModuleNotFoundError` errors during the test collection phase, preventing any tests from actually running.

My investigation shows that the command is executing a globally-installed version of pytest from `/home/jules/.local/share/pipx/venvs/pytest/bin/python` instead of the one within the project's virtual environment (`.venv`). This means none of the project's dependencies are available to the test runner.

This is the highest priority issue and blocks all other development and verification work.

## Acceptance criteria (BDD)

**Scenario:** Running the test suite in a clean environment
**Given** a fresh clone of the repository
**And** the environment is set up using `uv venv` and `uv sync --dev`
**When** the command `uv run pytest` is executed from the repository root
**Then** pytest should successfully collect all 36 tests
**And** no `ModuleNotFoundError` or other collection errors should occur
**And** the test session should start and attempt to run the collected tests.

## Constraints / Non-goals

- **DO NOT** modify individual test files to fix imports. The issue is environmental, not in the test code itself.
- **DO NOT** install packages globally or using `pipx`. The solution must be self-contained within the project's `uv` environment.
- It is **NOT REQUIRED** for all 36 tests to *pass*. The goal of this task is only to ensure they are all *collected* successfully. Fixing failing tests will be handled in a subsequent thread.

## Requested actions

1.  Diagnose the root cause of why `uv run pytest` is failing to use the project's virtual environment.
2.  Implement a fix that ensures `uv run pytest` executes using the interpreter and dependencies from the `.venv` directory. This might involve changes to `pyproject.toml` or other configuration files.
3.  Verify the fix by running `uv run pytest` and confirming that all 36 tests are collected without error.

## Definition of done

- The `uv run pytest` command completes the test collection phase with "collected 36 items" and 0 errors.
- The fix is committed to the repository.
- You have sent an `ACK` message for this `BRIEF`, including a short summary of the root cause.
