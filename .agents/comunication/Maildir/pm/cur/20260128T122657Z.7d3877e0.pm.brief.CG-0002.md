## Summary
The project's test suite is critically failing. The root cause appears to be an environment issue where `uv run pytest` is not executing within the project's virtual environment (`.venv`), but is instead using a globally-installed `pytest`. This results in `ModuleNotFoundError` for all project dependencies, preventing any tests from running.

## Acceptance criteria (BDD)
```gherkin
Scenario: Test suite runs successfully within the project environment
  Given project dependencies are installed via "uv sync --dev"
  When the test suite is invoked via "uv run pytest"
  Then the command MUST use the interpreter and dependencies from the local ".venv"
  And all tests are collected and run without "ModuleNotFoundError"
```

## Constraints / Non-goals
- **Do not** modify the dependencies listed in `pyproject.toml`. The dependency list is correct.
- **Do not** install dependencies globally. The solution must ensure the project's isolated `.venv` is used.
- **Do not** change the test runner from `pytest`.

## Requested actions
1.  **Diagnose:** Investigate why `uv run pytest` is failing to use the local virtual environment. Check `uv`'s configuration, the project's `pyproject.toml` settings, and any potential PATH issues.
2.  **Implement Fix:** Apply the necessary changes to ensure `uv run pytest` correctly executes using the `.venv` interpreter and its installed dependencies.
3.  **Verify:** Run the test suite and confirm that all `ModuleNotFoundError` errors are resolved and tests are collected successfully. The tests themselves may still fail, but collection must succeed.

## Definition of done
- The command `uv run pytest` executes without any `ModuleNotFoundError` exceptions.
- The command successfully collects all 25 tests.
- A successful run of `uv run pytest` is demonstrated in the pull request, showing successful test collection.
