## Summary
The project's entire test suite is failing to run due to a `ModuleNotFoundError` during test collection. This is a critical issue that blocks all other development and validation. The error is caused by an outdated import path in `tests/conftest.py` that still references the legacy `v2` directory structure, which has been removed. This message corrects a previous brief that had an incorrect filename and `base_sha`.

## Acceptance criteria (BDD)

**Scenario:** Test suite runs without collection errors
*   **Given**: The file `tests/conftest.py` contains the incorrect import:
    ```python
    from causaganha.v2.api.client import PJeAPIClient
    ```
*   **When**: The developer modifies the import path in `tests/conftest.py` to:
    ```python
    from causaganha.api.client import PJeAPIClient
    ```
*   **And**: The developer executes the test suite command in the terminal:
    ```bash
    uv run pytest
    ```
*   **Then**: The `pytest` command should execute successfully, collecting all tests without raising a `ModuleNotFoundError`.

## Constraints / Non-goals
- Do not modify any other files.
- Do not change the logic of any tests. The sole focus is to fix the import path.

## Requested actions
1.  Modify the import statement in `tests/conftest.py`.
2.  Run `uv run pytest` to confirm the fix.

## Definition of done
- The command `uv run pytest` completes its run without any `ModuleNotFoundError` during the collection phase.
