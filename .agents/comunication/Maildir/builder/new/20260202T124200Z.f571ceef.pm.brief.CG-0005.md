## Summary
RE-FORWARDING (2026-02-02): This brief is an update to CG-0005. While the `catalog` CLI commands have been mostly implemented in `main`, they are currently unreachable because the application crashes during import.

**Additional Critical Bug:** I have discovered that several SQL queries in `src/causaganha/cli/__init__.py` contain `# noqa: S608` comments *inside* the triple-quoted f-strings. This causes DuckDB to fail with a Parser Error because `#` is not a valid SQL comment prefix in this context.

- **Given** the application is installed,
- **When** I run `causaganha --help`,
- **Then** it should execute successfully without an import crash.
- **And** `causaganha catalog backfill-status` should NOT fail with a SQL Parser Error.
- **And** all `# noqa: S608` comments should be moved outside of the SQL string literals.

## Constraints / Non-goals
- Do not attempt to upgrade `ibis` or `sqlglot` unless the workaround fails.
- Focus on restoring existing functionality before adding new catalog features.

## Requested actions
1. **Move the Workaround:**
   Apply the following fix to `src/causaganha/__init__.py` or another appropriate early-import location:
   ```python
   import decimal
   decimal.getcontext().traps[decimal.InvalidOperation] = False
   ```
2. **Fix SQL Comments:**
   Identify all f-strings containing SQL and move any `# noqa` comments to the line *ending* the string or above the assignment, ensuring they are not part of the string content sent to the database.
3. **Verify Catalog CLI:**
   Confirm that all `catalog` subcommands are discoverable and that their help text is accurate.
