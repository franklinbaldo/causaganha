# Goal: CNJ lookup in decisoes_buscar stops scanning every JURIS partition (#1238)

Sem issue nova nem PR aberta nesta rodada (a fila de trabalho estava genuinamente vazia — ver `reading-issues`), usei um agente Explore para investigar o código em busca de uma lacuna real. Ele encontrou `plan_decision_search`'s caminho `consulta_por_cnj=True` sem nenhum bound quando não há datas. Verifiquei ao vivo contra o manifesto real de produção: **1051 arquivos Parquet JURIS publicados hoje**, de 1989 a 2026 — ou seja, toda chamada atual de `decisoes_buscar(cnj=...)` já abre 1051 arquivos remotos via DuckDB httpfs, não é um risco futuro. A correção reaproveita `indice_processual.parquet`, o índice fino que `processo_consultar` já usa para resolver exatamente qual arquivo tem o registro JURIS de um CNJ — exatamente o que o próprio docstring do planner já presumia existir.
