# Goal: resolver o bucket `verify_values` com leitura real de valores

`read_footer_stats` só lê o rodapé Parquet -- nunca uma linha de dado real -- então todo arquivo de um único grupo (ou com limites nulos) fica permanentemente em `verify_values`, mesmo quando a coluna CNJ já está de fato ordenada no arquivo físico. O próprio critério de aceite da issue #1470 pede exatamente essa verificação de valores para os casos inconclusivos. Implementar uma checagem real (ordem física da coluna `numero_processo` via scan nativo do Parquet, sem tocar footer apenas) que reclassifica cada um dos 8 arquivos hoje presos nesse bucket em `verified_sorted` ou `verified_unsorted`, mantendo `verify_values` só para uma falha de leitura genuína.
