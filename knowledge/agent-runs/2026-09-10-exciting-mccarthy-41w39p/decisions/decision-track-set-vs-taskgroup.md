# Decisão: conjunto de tasks rastreadas + await no finally, não TaskGroup

`run_pipeline` já gerencia suas próprias tasks de worker com `asyncio.create_task` + `gather` explícito em vários pontos da função -- introduzir `asyncio.TaskGroup` só para esta task de background misturaria dois idiomas de concorrência sem ganho, e seu cancelamento automático dos irmãos ao primeiro erro não é desejado aqui (o upload já trata suas próprias exceções internamente e nunca deve cancelar os workers). Preferido o idioma padrão da própria documentação do `asyncio` para tasks fire-and-forget: um `set` rastreado com `add_done_callback` para descarte automático, aguardado (não cancelado) no `finally` já existente -- porque, ao contrário das tasks-irmãs de `yd5lu0`, este é exatamente o trabalho cuja conclusão o shutdown precisa garantir.
