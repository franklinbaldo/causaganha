# Goal: correct dataAjuizamento across timezones

`toIsoDate` não deve reinterpretar via `new Date()` uma string de data/hora ingênua (sem `Z`/offset) -- isso trata hora local como se fosse UTC e desloca o dia calendário em qualquer fuso UTC+. `dataAjuizamento` (DataJud) é exatamente essa forma: `normalizar_data14` sempre produz `'YYYY-MM-DDTHH:MM:SS'` sem sufixo de fuso. O comentário do teste existente ("data_ajuizamento is a genuine DATE column") está factualmente errado e escondeu o bug.
