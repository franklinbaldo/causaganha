# Decisão: corrigir toIsoDate, não a origem Python nem o SQL

Escolhido extrair o prefixo `YYYY-MM-DD` diretamente de qualquer string de data ingênua (sem `Z`/offset) dentro do próprio `toIsoDate`, em vez de alterar `normalizar_data14` (perderia precisão de hora para outros consumidores Python) ou o cast SQL em `buildDatajudSql` (a coluna não é um DATE/TIMESTAMP real). Replica a mesma política já documentada em `toIsoTimestamp` para o campo irmão `ultima_atualizacao`.
