# Evidência: correção do CI vermelho na PR #1356

O check `web` da PR #1356 falhou por timeout de 120s no teste de integração `renderedContracts.integration.test.ts`. Causa raiz: a correção original desta rodada delega `_register_tjro_juris`/`_register_datajud_capa` para `reconcile_processos.ensure_juris_parquets()`/`ensure_datajud_parquets()`, que leem seus próprios caminhos locais (`ROOT`/`DATA_DIR`/`_DATAJUD_DIR` do módulo `reconcile_processos`), não o `renderer.ROOT` que `render_contract_fixture.py` já redirecionava. Sem arquivos locais visíveis, essas funções caíam no fallback real de rede para o IA dentro do sandbox do vitest — reproduzido localmente (20s+ de download real antes de ser interrompido). Corrigido substituindo (`monkeypatch`) `ensure_juris_parquets`/`ensure_datajud_parquets` diretamente em `render_contract_fixture.py`, no mesmo padrão já usado por `tests/test_render_queries.py` e pelo próprio script para `_register_comunicacoes`. Teste de integração volta a passar em ~2s; suíte web completa (70/506) e suíte Python completas, verdes.
