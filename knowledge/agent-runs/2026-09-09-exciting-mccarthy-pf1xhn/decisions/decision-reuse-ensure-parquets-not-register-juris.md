# Decisão: reusar `ensure_*_parquets()`, não `_register_juris`/`_register_datajud`

Optei por reusar apenas as funções que retornam caminhos crus (`ensure_juris_parquets`/`ensure_datajud_parquets`), preservando o contrato booleano existente de `render_queries.py` (`False` = view ausente = fallback gracioso "não publicada" para contratos opcionais). Reusar diretamente `_register_juris`/`_register_datajud` teria mudado esse comportamento — essas funções sempre criam uma view (vazia quando a fonte está indisponível), o que é correto para o pipeline de agregação do `reconcile_processos.py` mas trocaria silenciosamente "cobertura não publicada" por "0 documentos" sempre que uma fonte estiver fora do ar. Fora do escopo deste bug.
