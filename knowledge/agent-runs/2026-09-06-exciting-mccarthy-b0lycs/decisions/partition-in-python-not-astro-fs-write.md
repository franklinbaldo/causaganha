# Decisão: particionar em Python, não com escrita de fs no Astro

A primeira implementação (escrever o particionamento de dentro do frontmatter de `stats.astro`, no mesmo padrão do SVG de OG em `/publicacoes/[tribunal].astro`) foi testada e não chegou ao `dist/`: o Astro copia `public/` para `dist/` antes de rodar o frontmatter das páginas, e `web/public/data/` é regenerado do zero a cada execução (sem estado versionado para "ficar uma build atrasado", como o SVG de OG). Mover o particionamento para `scripts/render_queries.py` — que já escreve `tribunal_calendar.json` no mesmo diretório antes do `npm run build` rodar — resolve isso corretamente, confirmado por rebuild e inspeção de `dist/`.
