# CausaGanha Web

The public CausaGanha site is a static Astro application deployed to GitHub Pages at `/causaganha/`.

Its UI foundation is **Cobogó + Panda CSS**. Astro remains the host and SSG is the default: Panda generates styling at build time, while Svelte is used only for interactive product islands such as process lookup, publication search, saved consultations and the DuckDB explorer.

## Product surface

The public hierarchy starts with two jobs:

1. **Consultar processo** — open a CNJ dossier and keep DJEN, DataJud, JURIS and STJ evidence distinguishable.
2. **Pesquisar publicações** — search preserved DJEN publications by CNJ, OAB, party or free text.

Secondary surfaces provide saved local consultations, coverage, advanced data exploration, MCP access and project/data documentation.

## Design system

Cobogó is installed as a real dependency pinned to a known repository commit. The consumer does not vendor Cobogó CSS.

`panda.config.ts` loads `cobogo/preset`, and the generated APIs live in `styled-system/` (ignored by Git). Astro pages use `styled-system/css` plus Cobogó recipes such as `button`, `card`, `badge`, `alert`, `table` and `navLink`.

The small `src/index.css` file exists only for global browser defaults and compatibility styling for existing Svelte islands while they migrate toward shared recipes. It is not a second design system.

## Stack

- Astro 7, `output: static`
- Panda CSS 1.12 + `cobogo/preset`
- Svelte 5 islands for interaction
- DuckDB-WASM for in-browser SQL
- TanStack Svelte Query where runtime freshness is required
- Observable Plot for data visualization
- Zod for generated-data validation
- Vitest + Testing Library + vitest-cucumber

There is no application server at runtime. Build-time contracts are rendered into `public/data` / `public/cache`, Astro pre-renders the pages, and browser islands progressively add interaction.

## Development

```bash
npm ci
npm run dev
npm run lint
npm test
npm run typecheck
npm run build
```

`prepare`, `prebuild`, `pretest` and `pretypecheck` run `panda codegen`, so the generated `styled-system/` API always reflects the pinned Cobogó preset.

The complete production build also depends on pipeline-generated data. The repository deploy workflow prepares those artifacts before `npm run build`.

## Layout

```text
web/
├── panda.config.ts       # consumes cobogo/preset
├── postcss.config.cjs    # Panda PostCSS integration
├── src/
│   ├── index.css         # thin browser/Svelte bridge
│   ├── layouts/          # shared Astro shell
│   ├── pages/            # static public routes
│   ├── components/       # interactive Svelte/Astro product pieces
│   └── lib/              # contracts, data loaders and browser logic
├── public/               # build-time/static data
└── styled-system/        # generated by Panda; not committed
```

## Rule of thumb

Visual decisions shared across Franklin projects belong in Cobogó. CausaGanha keeps only product-specific composition and behavior. New local CSS should solve a CausaGanha-specific need rather than recreate a token, recipe or primitive already owned by Cobogó.
